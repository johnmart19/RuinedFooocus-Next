# Deferred findings

Keep confirmed, non-blocking follow-ups here so a completed bounded task can stop.
Each card records one topic, exact source/evidence, impact, owner, next bounded
action and acceptance. Use the [template](TEMPLATE.md); add its row below in the
same change. A card authorizes no investigation, model acquisition or execution.

| ID           | Follow-up                                                                           | Status                                   | Owner                    |
| ------------ | ----------------------------------------------------------------------------------- | ---------------------------------------- | ------------------------ |
| RF-ISSUE-001 | [Shared still-image utility admission and dispatch](001-utility-dispatch.md)        | Deferred; steward-confirmed non-blocking | Generation/integration   |
| RF-ISSUE-002 | [Historical compact Chat qualification failures](002-compact-chat-qualification.md) | Default replacement deferred by user     | Chat/model qualification |

Preserve evidence at its original source and artifact identities. Mark historical,
missing or mocked evidence explicitly; source/CPU checks do not pass rendered UI,
model semantics, device, performance or stability acceptance. Link the owning guide
instead of copying a transcript or creating a wishlist.

Current acceptance blockers remain with their owners in the maintained
[acceptance inventory](../integrations/remaining-acceptance.md). Filing an issue
does not close those blockers or change their acceptance requirements. Only
confirmed deferred findings belong in the cards below.

Before deferring another finding, record the owner/steward's non-blocking
disposition and the working boundary that remains available. When resumed, perform
the card's next bounded action, then update its evidence and disposition. Promote
a reproduced current acceptance blocker back to active work. Close a card only
with the named acceptance evidence or an explicit change of requirement.
